# Frontend handoff

Снимок состояния: 15 июля 2026 года.

## Что уже сделано

- Введена единая тёмная визуальная система с glass-слоями, градиентами, адаптивными состояниями, плавными переходами и поддержкой `prefers-reduced-motion`.
- Пересобраны основной layout, верхняя панель и ролевой sidebar; активный канал и доступность пунктов зависят от роли.
- Исправлен вход: выбранная роль преподавателя или студента сохраняется и корректно влияет на роутинг.
- Добавлена содержательная главная панель для обеих ролей с быстрыми действиями.
- Полностью переработана библиотека ресурсов: локальные CSS-обложки вместо хрупких hotlink-картинок, поиск, категории, сортировка, закладки, пагинация и реальные ссылки.
- Переработаны экран лекции, список участников и live-чат; добавлены ролевые controls, реакции, ответы, вложения, лимиты сообщений и cleanup таймеров/listeners.
- Улучшены общий чат, emoji/file input, уведомления и безопасный рендер текста без пользовательского `v-html`.
- Тяжёлые функциональные экраны вынесены в отдельные route/component chunks там, где текущая архитектура это позволяет.

## Что необходимо завершить

### P0 — перед следующим релизом

1. **Завершить консолидацию `TeacherView.vue`.** Во время финальной параллельной проверки файл был случайно удалён и перед handoff восстановлен из стабильной версии с повторным подключением новой главной панели. Нужно снова перенести в него последние оптимизации: убрать недостижимые дубли веток, перевести Stream/Analytics/Assignments/Resources/Chat на `defineAsyncComponent`, удалить статический `chart.js/auto` и оставить Chart.js только внутри ленивой аналитики.
2. **Пройти ручной visual/click-through для обеих ролей.** Проверить desktop/mobile, переходы по всем пунктам sidebar, вход как student/teacher, модальные окна, focus/keyboard и длинные списки. Встроенная browser-сессия во время работы была недоступна, поэтому выполнены build и статические проверки, но не полный визуальный прогон.

### P1 — функциональность и устойчивость

1. **Синхронизировать чат с Pinia.** `MessageContainer` читает историю канала из store, но новые сообщения пока добавляет в локальный массив. Нужно писать через `channelStore.addMessage`, сохранять реакции и ограничить историю примерно 500 сообщениями на канал.
2. **Закрыть lifecycle вложений.** При вытеснении сообщений освобождать Object URL именно удаляемых вложений. Не отзывать URL истории при обычном переходе между каналами/экраном лекции, пока сообщение остаётся в store.
3. **Добавить лимиты файлов.** Ограничить ChatInput и StudentView по количеству вложений и общему объёму, а не только по размеру одного файла. Рекомендуемый предел: 8 файлов и 30–40 МБ суммарно.
4. **Довести профиль по ролям.** Преподаватель не должен видеть ученическую корзину и вкладку достижений. Данные профиля должны строиться из текущего пользователя, а не из демонстрационного «Петр Иванов». Таймер имитации загрузки нужно очищать при unmount.
5. **Защитить persisted state.** В расписании TeacherView/TeacherDashboard и закладках Resources проверять результат `JSON.parse` через `Array.isArray`; повреждённый localStorage не должен ломать монтирование экрана.
6. **Закончить режим объявлений.** Read-only уже отражён в Chat UI для студента; при переносе отправки в store необходимо также запретить запись на уровне store/action.

### P2 — UX и архитектура

1. **Довести TeacherDashboard или удалить legacy-route.** Сейчас `/teacher-dashboard` перенаправляет на основной teacher view, поэтому старый dashboard фактически недостижим. Если он остаётся, исправить безопасное редактирование расписания (не удалять запись до сохранения), календарь с повторяющимися ключами и заглушки создания курсов/заданий.
2. **Завершить i18n.** LanguageSwitcher меняет locale, но основной UI пока не переведён на `$t(...)`. До появления переводов лучше скрыть переключатель либо подключить словари и заменить строки.
3. **Сделать shortcut библиотеки реальным.** Подсказка `⌘/Ctrl + K` должна фокусировать поле поиска или быть удалена.
4. **Очистить устаревшие id каналов.** Удалить из StudentView/TeacherView проверки `chat`, `feedback`, `homework`, если эти каналы не возвращаются в `channels.js`.
5. **Убрать orphan assets/components.** Старый `VideoPanel.vue` не импортируется, но связанные PNG суммарно добавляют около 4 МБ к `dist`.

## Рекомендуемый порядок следующей итерации

2. Chat/store persistence, лимиты и Object URL lifecycle.
3. Profile role split и persisted-state guards.
4. Полный visual QA student/teacher на 1440, 1024, 768 и 390 px.
5. Удаление legacy-кода/assets и финальный bundle audit.

## Критерии готовности

- `npm run build` проходит без ошибок.
- Для student и teacher нет пунктов меню, ведущих в пустую или недостижимую ветку.
- Все видимые кнопки либо выполняют действие, либо явно disabled с объяснением.
- После 30 минут активного чата/стрима не растут без ограничения DOM, timers, listeners и Object URLs.
- Ни один основной экран не зависит от внешней картинки без локального fallback.
- Keyboard navigation и `prefers-reduced-motion` проходят ручную проверку.
